# Lumyte.Memory

リソース、Graphics、Audioに依存しないメモリ予算と所有権のコア機能です。

`MemoryManager`はpoolごとのsoft／hard limit、同時予約、確定済みcharge、見積もり量を追跡します。外部のGPU／Native資源は`ReserveAsync`、物理確保、`Commit`の順で接続し、物理資源を解放した後にchargeを返します。予測を超えた確保も台帳に残し、以後の予約を拒否します。

`RentAsync<T>`は呼び出したスレッドに対応するCPUチャンクから、要求長の連続した領域を切り出します。取得は同期的に完了し、チャンクはmanager・pool・要素型ごとに分離します。対応先は実際の実行スレッドなので、`await`後に別スレッドへ移った場合は移動先のチャンクを使います。同じスレッドの複数scopeは、生存中のチャンクを共有できます。

標準チャンクサイズは64 KiBです。コンストラクターの`chunkSizeBytes`またはDIの`ChunkSizeBytes`で変更できます。要素数はサイズ内に収まる整数に丸め、チャンクより大きな要求は要求長で確保します。標準サイズがhard limitに収まらない場合も、要求長で再試行します。チャンクの全capacityを一度だけ計上し、空き領域も予算に含めます。bufferの`Capacity`と`ChargedBytes`はそのbufferの領域を表すため、合計はpoolの`CommittedBytes`より小さくなることがあります。

チャンクの書き込み位置は取得スレッドだけが進めます。bufferは別スレッドからも返却でき、最後のbufferが返るとチャンクを終了して、その容量を台帳から除きます。返却済みの個別領域の再利用や、空チャンクの保持は行いません。同時に生存するbufferでチャンクを共有する方式なので、取得と返却を一件ずつ繰り返す場合は毎回新しいチャンクを確保します。スレッド側の参照は弱参照にし、スレッドの終了や再利用を解放の条件にしません。

取得・返却・予算計上・scopeの所有権更新には`lock`や待機ロックを使わず、`Interlocked`によるCASで競合を解決します。scopeを閉じると新規取得を止め、進行中の操作が終わってから残った所有物を解放します。bufferとscopeの解放は冪等です。scopeはDI scopeとは別の実行時寿命で、利用側が所有します。bufferの解放後は借用した`Memory`も使用できません。基盤となる配列や管理オブジェクトの確保は.NETのGCに従うため、実行時間の上限やGC停止の回避は保証しません。

回収は`ReclaimAsync`から明示的に開始します。予約失敗から自動的にreclaimerを呼びません。同じpoolの回収だけは`SemaphoreSlim`で直列化し、callback実行中の同poolへの新規取得・予約を拒否します。この待機は取得・返却経路には入りません。返却量はreclaimerの申告値ではなく、このmanagerの台帳で解放した実容量です。既存の予約が並行してcommitされても解放量を失わず、チャンクの一部を返しただけでは回収量に含めません。

標準DIとの接続は`Lumyte.Memory.DependencyInjection`を使用します。
