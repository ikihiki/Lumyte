# Lumyte.Graphics.Shared

グラフィックスバックエンドから `ProjectReference` で参照する共通実装ライブラリです。ソースのリンクコンパイルは使用しません。

- `ShaderDataLayout` は artifact の型 schema を読み、生成時の互換性確認と明示的な配置診断を行います。数値の再配置やPackは提供しません。

  `Data(artifact, target, name)`はtargetの展開・reflection解析・layout構築をartifactの寿命内で共有します。`Data(target, name)`・`Root`・`HasRoot`も不変のtargetごとに解析結果を再利用します。所有者は弱参照で結び付け、GPU資源を保持しません。別artifact・別target・同名の異なるschemaを分離し、公開されるshader codeのコピー契約を維持します。成功したlayoutだけを保存し、存在しない名前の問い合わせでキャッシュを増やしません。
- `ShaderBindingDependencies.Collect` は選択した要素から参照依存を収集し、privateな`VisitReferences`で循環と転送済み要素のreference-only metadataを扱います。数値snapshotではありません。
- `ShaderDataTransferState` は明示copyのmetadata overlayを管理し、submit成功後に公開します。
- `ShaderBindingData` と `WgslBindingSpecializer` は WGSL を使うバックエンドで必要な binding データと shader variant を生成します。Vulkan は参照依存metadataとlayoutを利用し、参照の GPU 表現は自身で生成します。
- `ShaderBufferBinding` はallocationと登録byte範囲を保持します。同じallocationでも異なる範囲は別bindingとして解決し、GetElementはそのbinding内の要素位置を指定します。
- `GraphicsDeviceLifetime` は各backendが観測したdevice lossを一度だけ記録し、保存済みの状態、通知、loss待機を共通管理します。

バックエンドが実装する `IShaderReference`、`IShaderDataSource`、`IShaderRawBuffer`、`IShaderDataLayout` は `Lumyte.Graphics.Abstractions` に定義します。バックエンド向けの公開 API を経由するため `InternalsVisibleTo` は必要ありません。利用側のアプリケーションは従来どおり共通 graphics API を使用します。

GPU同期とリソースの有効期間は利用者が管理します。このライブラリはGPU同期や転送命令の自動発行を追加しません。metadataキャッシュの初期構築と公開は内部lockで保護します。

`ShaderBindingDependencies`の収集と`ShaderDataTransferState`のmetadata overlayはbinding生成に必要な情報だけを保持します。既定では登録の失効、staging revision、command間依存の変化をSubmit時に再検証しません。各backendの実deviceでEnableValidation()を明示した場合に限り、nullableなGraphicsValidationが寿命・登録・scope・semaphoreを追跡し、ShaderDataTransferStateはcopy source reference metadataのidentityをSubmit前に照合します。

`SurfaceFrameLifetime`は取得・提示の局所状態を扱い、ネイティブ取得・提示の明示的な完了待機を提供します。GPU submissionを自動収集せず、GPU使用の完了は利用者が別途確認します。semaphoreのsignal／wait履歴、使用中resourceの保持数、検証callbackは管理しません。

無効時の責務は[GRAPHICS-0014](../../../docs/adr/graphics/GRAPHICS-0014-caller-managed-resource-validation.md)を維持し、明示的な検証を許可する一部変更は[GRAPHICS-0035](../../../docs/adr/graphics/GRAPHICS-0035-csharp-authoritative-shader-transfer.md)に記録します。

writerは同期呼び出し中だけ暗黙のC#位置を使い、完了後は不透明な参照identityだけを保持します。Wgpu/Browserのstorage poolとremap laneはArgumentTable登録のShaderBufferAccessから決定し、BufferUsageやshaderの文字列パスから推定しません。同一範囲のread/write登録も別laneを使用します。シェーダーとの配置・参照種別の整合性は明示的に有効化する診断であり、Debug／Releaseとも既定無効です。binding分類には使いません。

GraphicsValidationは、command記録をrollback可能な診断transactionとして保持し、Submit時にqueue状態の複製へアクセスを指定順で適用します。成功後だけ状態を公開するため、未提出・破棄・同期的に失敗したnative Submitは後続commandの状態を変えません。bufferはbyte範囲、textureはmip／layer別に追跡します。登録identity、親子、mapping、binary semaphoreとmetadata copyの順序も診断します。GPU内部の動的アクセスは登録範囲として保守的に扱い、直接のnative操作やstaging byte変更は観測できません。D3D12の部分発行済みnative操作や非同期GPU失敗を取り消す保証はありません。

有限のnative bindingの構築とpassの使用宣言の照合は通常のadmission契約です。ShaderRootArgumentsはprepared passごとに一つ保存したActionを保持し、各native実行で最新の全参照集合をpass宣言のnative resource identity・byte範囲・accessと照合します。Actionは不変の許可配列だけをcaptureし、owner・context・pass・元入力を保持しません。これは任意診断のcallbackではありません。これは任意の寿命・barrier・semaphore診断と分離して維持します。通常の依存収集も診断delegateを作らず、型identityまたは生成型の配置providerだけを保持します。

## 参照付きuploadのmetadata

IShaderDataSourceはReadReferences／SetTransferredReferencesを提供します。IShaderReferenceMetadataはimmutableな依存identityのReferencesだけを公開し、各backendのprivate ownerはnumeric Data、wire offset、元の値objectを保持しません。旧ShaderReferenceMetadataクラスとValues adapterは削除しました。ShaderBindingDependencies.Elementsもreference-onlyです。CopyFromの失敗は部分byte更新を許し、要求範囲のmetadata全体を無効にします。全範囲の明示再転送で回復し、rollbackや隠れた数値履歴は提供しません。

## Set時の最終ルート格納領域

ShaderRootArgumentsは参照metadataと任意のbackend storageを所有します。Vulkan／D3D12はstorage: nullで作成し、数値を保持しません。Storage getterはstorageなしでInvalidOperationExceptionとなり、Seal／Disposeはmetadata世代の状態を扱います。公開Allocate(root, name, size, factory)は正確な論理sizeをfactoryへ渡し、codecを実行しません。Sharedは16-byte切り上げや最小容量を要求せず、返却容量が非負かつ論理size以上であることだけを検査します。公開Create(rootParameter, shaderTypeName, wireSize, storage, references, prepare)はnullable storageがある場合だけ容量を検証し、任意の参照準備が成功して戻るときだけstorageの所有権を受け取ります。失敗時の所有権は呼び出し側に残ります。generic codecやencode callbackをSharedへ渡すAPIはありません。各backend内部のShaderTransfer helperがwriterを直接呼び、書き込み・準備・Create失敗では未公開storageを解放して元の例外を保持します。Create後のcommandへの所有権移転失敗はSelectRootが扱います。Set成功時だけ新しいcommand所有世代を公開します。安定した参照表現はSet中に符号化し、不正な参照などで失敗しても前回の選択を保ちます。初回実行でsealし、後続実行は同じ世代を書き換えません。

ShaderBindingDependencies.Collect(rootArguments, …)は依存metadataだけを収集し、ArgumentsとRootParameterを公開します。numeric Root、ShaderValueSnapshotを受けるCollect overload、CreateSnapshot、Pack／SharedPackRawと遅延fixupはありません。ShaderBindingDataは実行ごとに間接依存とWGSLのdynamic pool／remapを再構築します。Graphのadmissionは診断無効時も機能します。graph encoderごとに一つ保存した準備delegateを既存IRenderEncoder／IComputeEncoderのSetArgumentValidationへSet中だけ設定し、finallyとEnd前に解除します。準備でroot参照をpass宣言と照合し、table自動選択後に新rootを公開します。Set中のEndやpipeline変更などの再入は拒否します。通常nativeのnull経路にhook用allocationはありません。JoinTableによるnative table統合だけではpassの使用宣言になりません。別callbackで取得して保存した参照は、使用passの宣言がresource・範囲・accessを許可し、native tableも互換なら使用できます。Graphはnativeのcommand-local metadataを観測できないため、この接続が必要です。

## 値だけを渡す同期writer

IShaderValueWriterの必須抽象メソッドは`WriteValue(ReadOnlySpan<byte> value)`と`WriteReference<T>(IGpuRef<T>? value)`だけです。offset、size、pathや位置移動は渡しません。各backend内部のVulkanShaderValueWriter、Direct3D12ShaderValueWriter、WgpuShaderValueWriter、BrowserShaderValueWriterが暗黙位置とexpectedTransferSizeを持ちます。Setと型付きCopyFromの両方で各backendのShaderTransfer helperがvalue.Write(ref writer)を呼びます。writerはraw区間をVulkan／D3D12のroot span、Wgpu／BrowserのrootのWriteまたはuploadのCopyBytesFromへ直接送り、参照はstackalloc byte[16]をクリアしてその場で符号化します。数値だけならパディング込み全wireを一回のWriteValueでコピーします。減算による残容量検査とComplete時の完全サイズ一致を要求し、spanを保持しません。

生成型はprivate unmanaged wireのローカルコピー後、実際のC#オフセット順にraw区間と参照を送ります。private static planは順序と妥当性に限定し、不正planはgetter前に拒否します。custom／virtual getterも物理順で一回だけ評価し、emitter structは生成しません。IShaderWireSink、IShaderReferenceCursor、IShaderReferenceEmitter、ShaderWire、ShaderWireCursorとWriteWireは削除済みで、互換aliasを残しません。

準備失敗では未公開storageを解放して旧root選択を維持します。native実行はCopyFrom／CopyBufferの最新command-local overlayを含む推移的参照を再収集し、ShaderRootArguments.Admitを呼びます。admission失敗はnative記録を阻止しますが、CPU状態のrollbackは保証しません。Graphのcopy overlay代理や数値snapshot、codec再実行はありません。

SharedのShaderTransferWriter、IShaderTransferDestination、ShaderRootDestination、ShaderUploadDestination、ShaderDataUpload、ShaderReferenceEncodingとVulkan／D3D12の旧参照encoderは削除し、汎用callbackへの迂回を残しません。任意診断はValidateReference(Type, object?, int)へ型・参照・現在位置を渡し、native参照ごとのShaderValue、new byte[16]やencode delegateを作りません。Vulkanは内部の型付きbuffer handleでShaderHandleのobject boxingを避けます。identity list、配列、read-only wrapper、immutable metadata owner、Wgpu／Browserのroot payload allocationとdelegate、実行ごとのbinding／descriptor heap確保は残り、zero allocationやGPU copy削減の実測は主張しません。Browserのinterop span-copyも残ります。

IShaderArguments.Capture／ShaderTransfer.CaptureとShaderValueSnapshotは明示検査・診断専用です。配置検査のFields、reflectionと手書き型の静的metadata取得補助は残しますが、backendの書き込み入力や実行admissionには使いません。ModelVertexの配置検査もUnsafe.SizeOfとFieldsを使い、Captureしません。通常の数値bufferの直接memcpyとGPU copy commandは変更しません。これはシェーダー転送の契約であり、無関係なコンパイル経路などの代替処理を除去する判断ではありません。

## backend-privateな転送方式

共通状態・Graph metadata・所有権・寿命はuniformを仮定しません。IShaderRootStorage.Write／Sealはopaque payloadの同期書き込みとcommit／freeze契約であり、共通のGPU uniform寿命方針ではありません。SharedのShaderBindingDataではuniform容量を検査せず、backendに任せます。Vulkan／D3D12のref struct writerはceil(wireSize/4) wordの有界stack spanをクリアして書き、Complete、任意診断、prepare、metadata作成とKeepBindingをすべて終えてから、Setが戻る前にnative定数commandを記録します。一時stackは最終payload ownerではなくdriver command bufferがコピーを所有します。CPU heap数値配列やArrayPool rentalは保持せず、Draw／Dispatchは数値を再送しません。Wgpu／Browserだけがbackend-private uniform emulationの最小16 byte・16-byte整列とnative binding上限を扱います。共通コードにWgpu／Browser feature dispatchは加えません。

Vulkanの容量はVulkanDevice.MaxPushConstantsSize、D3D12はDirect3D12Device.RootConstantDwordCapacity=58／RootConstantByteCapacity=232を参照します。Setでの超過は確保・公開前に拒否し、uniform fallbackを行いません。さらにartifact容量は任意validationと独立した必須ABI検査です。Vulkanは所有deviceに対してshader module生成前、D3D12は全pipeline／partial経路でnative pipeline生成前に検査します。全app ConstantBufferを実際のroot名でShaderDataLayout.Root(target, name).Sizeの論理容量から検査し、lumyteDrawInfoと__lumyte_schema_は除外します。論理232 byteの宣言padding240 byteは58 DWORDだけを読むため許可します。target別shader emitterがVkPushConstants／D3DRoot32BitConstants／UniformBufferを出し分けることは、runtimeの共通所有モデルがtransport非依存であることと両立します。

Vulkanのpush rangeはbind pointごとにoffset 0・物理容量へ固定し、computeの全variantはCompute、graphics／partialの全variantはVertex|Fragmentを使います。Setのstage maskは対応rangeと完全一致し、compute／graphicsのnative push状態を分離します。descriptor visibilityは独立にVertex|Fragment|Computeを許容し、descriptor数の違うlayout全体を同一にする契約ではありません。物理容量検査に加え64 KiBのbackend host stack guardで異常に大きい入力を拒否し、fallbackしません。256 byteは観測deviceの値です。D3D12はdevice初期化時にthread-safe cacheで一つの固定64 DWORD root signature（app 58、table各1、draw 2、SRV 2）を作ります。graphics／compute root pointerを別々に追跡し、同じsignatureのPSO／SetProgram変更では再bindによる定数resetを避けます。

IShaderArguments.`Write<TWriter>`の制約は`where TWriter : IShaderValueWriter, allows ref struct`です。C# 13以降と固定.NET 10 SDKを使い、公開writerの二メソッド・各一引数・offsetなしは変えません。host検査や準備hook失敗ではnative定数を発行せず旧選択を保ちますが、発行済みvoid driver commandやdevice failureのrollbackは保証しません。

Vulkan／D3D12のrender／compute全四encoderはcodecとprepare中を_settingArgumentsで保護し、入れ子のSet、pipeline変更、End、Draw／Dispatchなどの再入を拒否します。Graph準備のtable自動選択に必要なSetArgumentTableだけは許可します。callback後は、捕捉したpipelineのValidateAlive、owner.ValidatePassとpipeline identity一致をすべてKeepBindingとnative発行より前に再検査します。raw command bufferやpipelineのDisposeがguardを迂回しても、解放済みhandleを使うnative発行を阻止します。host失敗では旧root選択を保持しますが、呼び出し側が明示したresource Dispose、table自動選択や発行済みdriver commandは取り消しません。
