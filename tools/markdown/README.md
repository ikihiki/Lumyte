# ADR の Markdown 検査

通常の `mise run check-markdown` と CI の `CheckMarkdown` で、標準 Markdown 規則と ADR 専用規則を実行する。ADR 専用規則は `docs/adr/**/*.md` にだけ適用する。

| 規則 | 検査する内容 |
| --- | --- |
| LMADR001 | ファイル名・カテゴリとタイトルの一致、識別子の重複、状態の5値、実在する日付、基準SHA、必須見出しの順序 |
| LMADR002 | 「決定」内の「利用者の変更前・変更後」と、その説明がAPI差分より先にあること |
| LMADR003 | 具体的なPR・Issue番号、不許可の外部参照、相対ADRリンクの存在、ソースリンクのSHA固定 |

コードフェンス内のサンプルは本文の検査対象にしない。テンプレート内の見出しで必須項目を満たすこともできない。内部変更は「利用者の変更前・変更後」の節で記述が変わらない旨を説明でき、同じコードを二度掲載する必要はない。

## 既存 ADR の段階的な移行

`adr-legacy.json` は導入時の main `fbc81051cbf0f4aa5d996237543765e02b8cfa5c` にある ADR の SHA-256 を固定している。改行コードをLFへ正規化した本文が一致する間だけ、ADR専用規則を免除する。標準 Markdown 規則は常に実行する。

新規ファイルと本文を変更したファイルは免除されない。ファイル名の変更、front matterやコメントの追加でも免除は失効する。既存の採用判断を一括で書き換えることなく、修正する文書から新しい書式へ移行するための仕組みである。過去の重複識別子が別カテゴリの修正を妨げることはないが、新規・修正ファイル自身の識別子が衝突すれば拒否する。

この一覧を現在の作業ツリーから再生成してlintを通さない。追加・ハッシュ更新は通常の文書修正に含めず、移行方針の変更としてレビューする。移行が完了したファイルの項目は削除できる。

## 規則のテスト

リポジトリで固定した markdownlint-cli2 の依存を使い、実際の Markdown パーサーを通して検証する。

```sh
node tools/markdown/adr-rules.test.mjs
```

通常は `mise which markdownlint-cli2` からパッケージを解決する。別の場所に同じ版を用意した場合は、`MARKDOWNLINT_CLI2` にCLIの実行ファイルを指定する。リポジトリへ追加のnpm依存をインストールする必要はない。

## レビューで確認する内容

lintは文章の意味や設計判断の正しさを判定しない。特に、利用例が同じ目的の変更前後か、必要な所有権や失敗条件を省いていないか、過去ADRが基準コミットに存在するか、ソースの説明がその時点のコードと一致するかはレビューで確認する。

Gitの履歴取得やネットワーク通信はlint中に行わない。浅いcheckoutでも書式検査は同じように実行できる。基準SHAの存在・一意性、参照時点、ソースURLのファイル実在は、レビュー時にGitで確認する。識別子や節名の単なる本文への言及から、将来の判断への依存を自動で判定することもしない。
