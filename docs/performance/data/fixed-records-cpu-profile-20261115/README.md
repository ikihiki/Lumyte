Analyzer adapts the existing ui-device-trace TraceEvent reader. Exact paired BDN WorkloadActual/Start and /Stop windows exist in all eight extra diagnostic processes; setup, JIT, pilot, warmup, overhead and cleanup are excluded. No fallback guessed window was required. Compact tracked JSON truncates stack depth/top ranks; full local analysis retains complete stacks. Other runtime suspensions (including sampling-related SuspendOther) are counted separately, not GC pauses. Each JSON retains window endpoints, self/inclusive/nearest frames, top root-to-leaf calltree paths, runtime allocation ticks/stacks and GC events. Inclusive counts overlap and must not be summed. Percentages below use **managed samples only**, not elapsed time; external samples (mostly blocked waits) are separately retained, not busy CPU. Managed sample counts are modest and JIT inlining can hide methods. Native driver/Vulkan CPU and GPU timestamps are unmeasured. WaitNative/completion threads are not preparation CPU or GPU duration.

All eight traces have zero lost events, duplicate starts, unmatched begin/end, stage/parent mismatch, missing counter span, counter identity mismatch or missing parent. Span keys include provider/run/frame/span; counter joins validate stage and parent. Guid.Empty/frame 0 are never assigned to another frame. Stage CPU attribution uses the narrowest matching same-thread span only; continuation samples without a same-thread span stay unassociated (not nearby-frame guessed). Stage wall durations can contain awaits and nested overlap; do not add them into a total. Current captures emit Drawing2D spans; requested RenderGraph/UI providers emit no events on this fixture, not fabricated Graphics provider events.

## Next isolated comparisons (not implemented)

1. **Path clipping repeated-work elimination first.** Inspect Rendering/DrawRecordPage2D.cs TrySharedClip/Clip/CanAdmit and PreparedRecordBatch2D.PrepareAsync, plus normalized-clip identity/numerical equality. Avoid repeated full mask comparisons/copies and duplicate admission traversal while preserving exact clip coverage, painter order and budgets. The measured 66.5% normalization plus 14.5% packing/dedup dominate; direct-record lowering alone addresses the smaller 4.5% intermediate-compiler group. Prove invalidation and equality before caching.
2. **Retained owner accounting independently.** Execution/RetainedDrawingCache2D.cs OwnedBytes builds a fresh Dictionary<object,long> and traverses owners during statistics, admission and retirement. Both production lifecycle and the benchmark's two RetentionStatistics reads hit it; do not attribute all observer-triggered cost to an application. Compare incremental exact owner accounting without changing completion-safe lifetime/budget semantics. This is evidenced in both rectangle modes, not a generic pooling suggestion.
3. **Fixed-record storage growth separately.** PreparedRecordBatch2D / DrawRecordPage2D list growth accounts for 206.6 KiB/frame sampled DrawRecord2D arrays in dynamic rectangles and substantial Vector4 growth in paths. Compare bounded capacity reservation/reuse with identical admission, ownership and retirement, before broad pooling or another API. Stream upload/copy exists but is not the dominant observed managed CPU stack here; do not prioritize it from source alone.

No speedup from these proposals has been measured. ADR remains unchanged; performance interpretation belongs in this evidence and PR body.
