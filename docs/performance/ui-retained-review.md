ウォームアップ後5 batchの平均値の中央値です。Release、同じSDK・runtime・Parley native、tiering無効・workstation GC、同じ共有Linux環境で順次実行しました。shaping・setup・assertion・出力は計測外です。測定中はbuildを実行していません。IMEの文書revision・geometryとWindow要求の終端状態を検証しました。

[ハーネスと実行手順](../../tools/benchmarks/ui-retained/README.md)、[環境と全batchの生データ](ui-retained-review.json)を保存しています。

IMEの無変更時はgeometry配列の生成とbackendへの公開を省きます。範囲再生成は区間索引を使います。Windowの待機は完了履歴を走査せず、内部chromeの結果は明示解放します。Editor検証は構造revisionが変わるまで再利用します。

Signal再構築の全体粒度は維持しています。recipeと走査集合の再利用で割当は減りましたが、1,000要素では引き続きMB単位の確保が発生します。部分木境界の導入は別設計とし、この変更を部分木更新の実装とは扱いません。

GPU FPS、実OS IME、p99入力遅延、host全turnは測定していません。GPU変更は有界submit queue・退役・待機失敗のCPU fixtureで検証し、実機の並列提示性能とは区別します。

Signalの短い計測では時間のばらつきがあったため、`--signal-only`で100回/batchへ増やして再確認しました。同じ再構築は変更前1.738ms・2,633,992B、変更後1.488ms・2,164,408Bでした。短い全体測定の結果も上表と生データへ残し、CPU時間の改善幅を保証するものとは扱いません。
