# ADR-GRAPHICS-0012: 非圧縮カラーテクスチャ形式の拡充

- 状態: 採用
- 日付: 2026-10-10

## 背景

単チャンネルのマスク、2チャンネルのデータ、HDRの中間描画先にはRGBA8以外の格納形式が必要になる。

## 決定

非圧縮の正規化整数と16bit浮動小数点を追加する。既存の列挙値は維持する。
コピーのサイズとオフセット制約はGetTextureCopyLayoutから取得し、利用者が明示的に転送する。
形式の追加はあらゆるデバイスでの使用可否を保証せず、使用方法が非対応なら生成時に拒否する。
実装の形式対応は各バックエンドのREADMEに記載する。

### 公開API差分

比較元: main `5600df7`。名前空間は`Lumyte.Graphics.Abstractions`。

```diff
 public enum TextureFormat
 {
+    // Rの8bit正規化整数。1 byte/texel。
+    R8Unorm,
+    // RGの8bit正規化整数。2 bytes/texel。
+    Rg8Unorm,
+    // Rの16bit浮動小数点。2 bytes/texel。
+    R16Float,
+    // RGの16bit浮動小数点。4 bytes/texel。
+    Rg16Float,
+    // RGBAの16bit浮動小数点。8 bytes/texel。
+    Rgba16Float,
+    // RGB各10bitとalpha 2bitの正規化整数。4 bytes/texel。
+    Rgb10A2Unorm,
 }
```

格納形式の変更による数値変換はコピーで行わない。同じ形式間でバイトを保持する。
深度・ステンシルの使用契約は変更しない。整数サンプリング、32bit浮動小数点、圧縮形式の契約は別途設計する。

## 検討した代替案

すべてRGBA8へ変換すると、HDRの値域を失い、単チャンネル用途のメモリ量も増える。
全形式を一度に追加すると、整数サンプリングや圧縮ブロックの契約まで変更が必要になるため、今回は非圧縮のfilterableなカラー形式を対象とする。

## 結果と影響

マスクやHDRに適した形式を選択できる。コピーの行サイズとネイティブの描画先形式を形式ごとに扱う必要がある。
共通APIのサンプルで全カラー形式の生成とview、パディング付き複数レイヤー・mipの往復コピーを検証し、既存CIで各実装を実行する。
