# ADR-INPUT-0002: アナログ加工・入力バッファ・ジェスチャーと複合操作

- 状態: 提案
- 日付: 2026-10-09

## 背景

[Input 基盤](INPUT-0001-input-system.md)は正規化されたデバイス別記録を提供する。ゲームではデッドゾーンや筆圧カーブ、操作の先行受付、ピンチや長押し等が必要となる。これらを利用者ごとに実装すると、時間判定・キャンセル・履歴欠落への対応が分散する。

## 決定

### 責務と配置

`src/Platform/Lumyte.Input.Processing/`、名前空間・パッケージ名 `Lumyte.Input.Processing` に加工・認識層を設ける。依存は `Lumyte.Input` と .NET のみとする。InputSystem の記録・保持方針は変更しない。

利用者は独立した処理インスタンスとカーソルを持ち、ReadRecords から得た記録を Sequence 順に渡す。出力はデバイス ID、処理時刻、認識 ID と値を持つ不変の Signal とし、[アクション層](INPUT-0003-actions-and-contexts.md)へ渡せる。認識 ID は利用者が登録する文字列であり、操作名との対応付けはアクション層の責務とする。

### アナログ加工

処理順は正規化値 → デッドゾーン → 感度・反応曲線 → 必要なら平滑化とする。設定は登録時にコピーして固定し、元記録を変更しない。スティックは円形デッドゾーンを既定とし、半径 d 以下をゼロ、残りを `(r-d)/(1-d)` に再写像して方向を維持する。対角方向の半径は 1 にクランプする。

トリガーと筆圧は 0〜1 の範囲を維持し、非対応の筆圧 null を 0 に置き換えない。反応曲線は有限・単調増加、端点 0 / 1 を保証する。d は 0 以上 1 未満、感度は有限の非負値とする。平滑化は明示的に有効化し、単調時間差による指数平滑化を使う。フォーカス喪失・切断・キャンセル時は中立化し、平滑化の前回値を捨てる。

### 時間と認識

取り込み時刻 RecordedAt を共通時間軸とし、Advance の now は同じ InputSystem の開始からの単調経過時間とする。now は記録時刻以上かつ前回 now 以上でなければならない。入力なしでも Advance により長押し成立と期限切れを判定する。OS の実発生時刻精度は保証しない。

初期認識は次を対象とする。距離は対象領域の論理ピクセル、期間としきい値は設定可能とする。

| 認識 | 契約 |
| --- | --- |
| 長押し | 非リピート押下から設定期間経過で一度成立。成立前の解放でキャンセル |
| ダブルタップ・連打 | 同じ操作の押下・解放を数え、最大間隔以内の指定回数で成立。リピートは数えない |
| 同時押し | 指定キー・ボタンがすべて押下中で、最初と最後の押下差が許容期間内なら一度成立 |
| 順序入力 | 指定された押下列を順番・時間制限で認識。不一致はリセットし、その入力を新しい開始候補として再評価 |
| スワイプ | 一接触の開始から終了までの距離・期間・方向条件で成立。キャンセルでは成立しない |
| ピンチ・回転 | 同一デバイスの二接触を ID で固定し、距離比・角度差を継続出力。接触終了で終了、新しい組で基準を再設定 |

一接触の終了と合成キャンセルを区別する。異なるデバイスの接触はジェスチャーとして合成しない。認識同士は独立して評価し、基盤の記録を消費しない。認識結果の競合やUI優先順位はアクション・コンテキスト層で解決する。

### 入力バッファ

成立した Signal を利用者設定の期間だけ先行入力として保持する。TryConsume は条件に合う最古の一件を取り出し、一バッファ内で一度だけ消費する。消費可能な期間は `created <= now < expires` とし、期限ちょうどでは無効とする。別の利用者のバッファやInputSystem履歴は消費しない。

バッファの期間と最大件数は必須設定とし、満杯時は最古を削除して削除件数を結果で通知する。フォーカス喪失・切断・認識キャンセル時は対象デバイスの未消費入力を破棄する。利用者も明示的にクリアできる。

### 公開 API 一覧

新規 API の宣言案。メソッド本体と認識設定型の詳細は省略する。

```diff
+public enum SignalPhase { Started, Performed, Ended, Canceled }
+public sealed record InputSignal(
+    string Id, InputDeviceId DeviceId, TimeSpan At,
+    SignalPhase Phase, Vector2 Value);
+public interface IInputProcessor
+{
+    // 記録を加工・認識し、時間による成立も進める。
+    IReadOnlyList<InputSignal> Advance(
+        ReadOnlyMemory<InputRecord> records, TimeSpan now);
+    // 欠落・コンテキスト切替等で履歴依存の状態をリセットする。
+    IReadOnlyList<InputSignal> Reset(InputDeviceId device, TimeSpan now);
+}
+public sealed record InputBufferOptions(TimeSpan Lifetime, int MaxEntries);
+public sealed class InputBuffer
+{
+    public InputBuffer(InputBufferOptions options);
+    // 期限切れを除去後に追加し、容量不足による削除件数を返す。
+    public int Add(InputSignal signal, TimeSpan now);
+    public bool TryConsume(string id, TimeSpan now, out InputSignal? signal);
+    public int Clear(InputDeviceId device);
+    public int Prune(TimeSpan now);
+}
```

Signal の Value は、ボタン認識で (1, 0)、スティックで (X, Y)、トリガー・筆圧で (値, 0)、スワイプで移動ベクトル、ピンチで (距離比, 角度差ラジアン) とする。null の筆圧は Signal を生成しない。処理設定型と各認識クラスの完全な宣言は実装前に本 ADR を具体化する。

### エラーとライフサイクル

管理スレッドで処理し、スナップショットだけを他スレッドへ渡す。重複・逆順 Sequence、不正な設定、逆行時刻は例外として拒否する。HasGap を検出した利用者は Reset を呼び、関連バッファをクリアして現在状態に再同期する。欠落した履歴から複合操作を推測しない。

Reset は進行中の認識について Canceled を出力する。再同期時の押下状態は開始済みと扱わず、新しい押下・接触開始を待つ。Source や Device のリソースを所有しない。

## 検討した代替案

- InputSystem に認識を組み込む: 利用者ごとに異なる加工設定や処理周期を持てなくなる。
- 現在状態だけで認識する: 短い押下と順序を失うため、記録と単調時間を使用する。
- 一つの共有バッファを消費する: UIとゲーム等が互いの操作を奪うため、利用者別に管理する。

## 結果と影響

元入力を保存したまま用途別の加工・認識を組み合わせられる。利用者にはカーソル、欠落処理、時間進行とバッファ容量の管理が必要になる。平滑化と先行受付は操作遅延・誤受付に影響するため、既定で自動適用しない。

## 検証方針

デッドゾーン境界、筆圧 null、分割バッチと一括処理の一致、期限ちょうど、入力なしの長押し、リピート除外、二接触の入替・キャンセル、履歴欠落時の中断、複数利用者の独立性を検証する。

## 別途決定する事項

認識設定型と完全な公開 API、曲線の保存形式、複数接触の選択規則、OS発生時刻対応、性能目標は実装前に具体化する。本 PR は設計提案のみである。
